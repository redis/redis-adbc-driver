# Native unmanaged point-projection width ABBA comparison

512 complete native known-key width trial records: 128 warmups and 384 measured trials. Four payload layouts, one/four selected columns, one/four clients, unmanaged/redis-py. Not the standard CRUD/query matrix.

P50/means pool measured operation latencies; p95 uses nearest rank. Ratios use unrounded samples/statistics. All raw Redis controls and both complete pairs are retained without causal normalization.

Summed-trial throughput divides all measured operations by summed complete trial wall time; median-trial throughput is the median of per-trial rates. Finite closed-loop throughput includes coordination/scheduling, not saturated capacity. Means are not the inverse of concurrent workload completion rate.

Oracles independently describe exact selected/full-HASH source value bytes, not measured wire bytes, server CPU, allocation or causal latency attribution.

## Limits

- No NULL/ACL latency cases are timed here; all-selected-NULL and HGETALL-only principals can incur an extra read/fallback, including full payload transfer.
- The same index definition is used, but volatile FT.INFO statistics/reply lengths can differ.
- Independent build/image/runtime/server/helper freeze and actual chronological window records must accompany JSON metadata.
- The measured harness hash is preserved even if a later comment-only edit changes the local harness hash.
- Finite samples do not establish confidence intervals, production capacity or a general point-read/CRUD gain.
