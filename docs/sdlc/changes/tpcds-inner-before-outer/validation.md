Same method as [tpcds-equi-join-order](../tpcds-equi-join-order/validation.md):

- TPC-DS SF 0.1 generated by DuckDB 2.0.1, all 24 table counts checked after loading through the driver (4 GiB database). The data was reloaded into a fresh fixture for this change.
- macOS client through Docker's published port. Single cold runs with a full fetch, compared as row multisets against DuckDB with the harness tolerance.

## Q1–Q99 at SF 0.1

98 of 99 validated; Q35 still times out (EXISTS bodies run per outer row).

The new fixture was slower overall, including queries this change cannot affect. So the queries with outer joins (Q5, Q40, Q49, Q75, Q77, Q78, Q80, Q93) and five controls (Q2, Q4, Q13, Q14, Q23) were run alternately with a `main` library and this one, twice each, on the same fixture:
- Q75 went from 17.0/17.2 s to 5.7/5.4 s.
- Q78 was noisy on both builds: 26.2/26.9 s on `main`, 32.4/24.0 s with the change. Its outer joins keep the written order either way: one item before a LEFT JOIN, or an INNER JOIN after one.
- Every other query was within noise.
