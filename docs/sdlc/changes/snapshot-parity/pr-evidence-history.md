Managed queries could previously mix rows and schema from concurrent writes, and failed multi-batch ingest could leave partial data visible. Managed-table statement snapshots are now always enabled: each statement pins one immutable catalog generation, and writes publish their complete result with one atomic pointer change.

Writes share unchanged tables and append immutable row versions or tombstones. Durable background compaction copies bounded batches, resumes checkpoints and preserves newer deltas. SQL/Arrow input and uncertain cursor operations are never automatically replayed. ALTER, temporary objects, rename/rekey, HASH inspection/copy/import, foreign-index managed copies and live/retained partition production participate. Application data remains externally owned; explicit refresh captures a new managed copy.

Live partition sets now retain the producer's generation across DML, ALTER, TRUNCATE, DROP/recreation, compaction and producer close. Version-3 descriptors have bounded admission lifetime, explicit `DROP PARTITION SNAPSHOT` release and independent active-reader pins. `adbc.redis.partition_snapshot_id` reports the release ID. Retained mode remains independently materialized replay.

Optimized reads resolve newer versions/tombstones before filtering, grouping or limits. Search candidates check newer exact directories before fetching surviving HASHes. Bounded immutable visibility masks enable exact per-segment aggregation, weighted AVG, DISTINCT/grouping sets and globally merged ordered scans with late projection. Parallel scalar/top-K and large tuple paths retain visibility rules and typed exactness proofs. Large masks and unsettled private indexes use authoritative fallbacks. Referenced-table index checks replace catalog-wide read admission checks, with per-statement immutable-source caching; missing referenced indexes/rows still fail explicitly.

Private outputs now build one sealed index after staging, covering CREATE/CTAS, DML, ALTER and TRUNCATE. Private SQL uses authoritative directories before that index exists. No-op UPDATE/DELETE build no index and publish no empty generation. Native/SQL input admission waits for the short compaction publication gate and for a full target lineage to compact, releasing intent pins while waiting. This occurs before SQL execution or Arrow consumption; uncertain operations are never replayed. Immutable source validation proofs are shared with the private workspace.

Metadata now shares immutable buckets and native values through a fixed map of at most 256 references. Only touched values are copied; original manifests can retire while their values remain referenced by later roots. Bounded retirement, object presence checks and deletion pruning preserve old readers and prevent deleted-name accumulation. Snapshot ownership replaces legacy prefix/index/name registries, and final sealing visits dirty tables. Native table descriptor objects now retain row segments independently of bucket aliases. Private copies acquire those edges before detaching shared metadata, and descriptor SET updates them in the writer fence. Reservation retains only owned outputs; publication no longer reads unrelated table descriptors or copies aggregate base references. Compaction jobs retain their own sources/outputs, and a durable zero-reference queue admits row reclamation without catalog-wide reference scans. Live external capture remains separate from managed-copy SQL/catalog reads. Publication now records original metadata dependencies, including reads before workspace reservation. A known root CAS refusal can merge only changed logical keys into a pinned latest generation, preserving colliding bucket entries and deletions. Changed read/target objects still conflict. Private outputs are sealed before rebasing; both original/latest pins and leases are checked. SQL, Arrow input, defaults, row staging and index construction are never replayed. Shared metadata collections can still conflict.

Metadata buckets now have exact ordered field directories and point lookups with reference/count proofs. Construction copies at most 64 references per call with a 1 MiB byte target and durable logical-key checkpoints. Partial targets and sources remain reference-owned, incomplete builds cannot publish, and abort/expiry retires their references. Lost step replies do not automatically replay SQL or Arrow. Total work still grows with the size of a touched bucket.

Compaction discovery now uses a durable dirty-table queue updated atomically with publication, reusing final validation's descriptors. Idle discovery reads no table descriptors; each pass considers at most 16 due candidates. Queue age survives updates, stale cleanup cannot remove newer work, and identity/prefix proofs allow claiming a source across newer deltas. Failed source candidates are deferred so healthy work can progress. Claims preserve the existing durable leases, checkpoints and reference protocol. Separate orphan-index/GC work can still list indexes.

Cluster API support from the preceding checkpoint includes RESP3/TLS, primary validation and hooks on newly discovered nodes. Distributed Search schema commands run outside Lua with pre/post writer admission; late private indexes are reclaimed. Exact metadata directories and committed counts reject incomplete manifests.

**Breaking storage change:** protocol 15 rejects legacy storage and draft formats 1–14 without modification; the new format uses shared metadata buckets/native objects, reference-counted retirement and the indexed tombstone field. There is no upgrade or downgrade path. Ordinary initialization needs an empty isolated database; explicit imports may initialize beside application data after rejecting legacy driver metadata. Autocommit only; one catalog still occupies one `{meta}` slot. Active-Active remains unsupported and noeviction is required.
